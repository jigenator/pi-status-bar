# Design

## Experience

The footer is for people supervising a Pi session that may cross repositories or worktrees. It should answer “what project and branch does the agent say it is working in, what is that checkout's state, and, when different, where do Pi's tools actually run?” without implying that the display controls execution.

The desired tone is factual and compact. Unknowns and failures are named; the interface never reassures with “clean” or “no open PR” when a lookup failed. The anti-goal is a dashboard with controls or cumulative usage/cost detail. Remaining subscription quota (USG) is in scope because it is a current limit, not a cumulative total.

The visual language is the selected Marathon-inspired “01 — Acid / Black” footer from Terminal Lab: a framed instrument panel with solid numbered label plates, a graduated context gauge, a wide-only context numeral, a model band, and decorative frame motion. Native v9 retains the selected Acid / Black palette and parent/current paths, with padded numbered plates, a tick-free scale and Thread Rail activity. The browser prototype is a visual reference, not production telemetry or a fixed-size terminal layout.

## Interaction and visual language

`set_active_project({ path })` is the agent's interaction. The agent calls it before deliberately moving work and when switching back. Relative paths resolve from Launch, the session's fixed working directory; valid Git paths normalize to checkout roots. Invalid or cancelled selections leave the previous Active value unchanged.

`/footer-motion [on|off]` is the only user control. An empty argument toggles. It settles or resumes decoration for the current session only, is not persisted, and never freezes live values.

The header always opens with an eight-cell **CMP** plate: the number of successful compactions persisted on the selected session branch, as ` CMP×00 `…` CMP×99 `, ` CMP×99+` above 99 (the `+` takes the trailing pad cell) or ` CMP×?? ` when unknown; `×` is the multiplication sign. CMP shows in plain folders and repositories without GitHub too. Beside it, on the content column of the rows below, the header carries a `■` (U+25A0) square, one field cell, then `owner/repository` and any open PR number or a PR unavailable reason. The square marks every GitHub title: acid for a known repository, otherwise the color of its state text (grey `■ GitHub pending`, amber `■ GitHub unavailable (reason)`). Naming the repository here is what lets the ACT row show only a branch. Repository-less lookups say `GitHub pending` or `GitHub unavailable (reason)` so they cannot be read as a CMP state. When no GitHub remote exists, the plate stands alone without repository text. In the framed layout one row, carrying the frame's side stubs, separates the header from the numbered rows. It is blank, or, when Pi's working directory (Launch) differs from Active, a plain grey `cwd` line with that path on the content column. Using this row keeps the numbered plates together and the footer height unchanged when the agent switches. The numbered rows then appear in this order:

1. ` 01 ACT `. When Active is a Git checkout on a known branch and the header names its GitHub repository, the row shows only `⑂` (U+2442) and the branch name as plain, unplated text in the context scale's secondary grey, then the status as bold colored text on the field, one cell after the branch: acid `clean`, amber `modified` or white `status unavailable`. It is text rather than a plate so it cannot merge with the acid gauge fill on the row below. The path is omitted because a branch identifies one checkout within a repository: Git does not check one branch out in two worktrees, and Active is always a checkout root. Otherwise the row shows the Active path, and immediately below the complete path (after any wrapping) an unnumbered Git-details continuation shows the same `⑂`, branch and status text, `detached @revision`, Git pending or Git unavailable; a plain directory has no Git line. Primary-checkout paths, state and unavailable messages are not rendered.
2. ` 02 CTX ` gauge with protected inline token readout and WARN/HIGH/UNKNOWN tag; at 100+ columns, when content fits, a tick-free number scale and three-row numeral sit beside the last ACT-block rows and the gauge.
3. ` 03 MDL ` provider/model and thinking level on the model band; the white ` ⌑ PNYTL // LTE ` plate sits on the same row when the natural model ends before the plate's left gap, otherwise continues on its own band row before EXT. Beside the large context numeral, the plate's white left edge sits on the digits' first column (its left gap under the spine's spacer) and the band continues after its right gap to the frame; without the numeral it right-aligns.
4. ` 04 USG ` subscription usage windows from the CodexBar CLI, after MDL and any PNYTL continuation row; see [USG usage limits](#usg-usage-limits). The row is absent when CodexBar is not installed or not yet detected.
5. ` 05 EXT ` plus one or more entries sorted by status key. Recognized key `ponytail` is represented by PNYTL instead; active validated `tatsu-status` becomes the structured Tatsu entry below, at its original sorted position. All other statuses, unrecognized Ponytail text, and raw Tatsu fallback stay verbatim in EXT.

Active and cwd paths show only the immediate parent and current directory, for example `Projects/pi-status-bar`. Home itself is `~` and a direct child of home is `~/name`. Root, a single component, and two-component paths are shown in full because nothing would be elided; relative values are shown as given. GitHub shows only `owner/repository`, without repeating its repository URL. Only PR numbers appear when an open PR is found; full PR URLs are omitted at every width. Confirmed absence and not-applicable states have no PR suffix. These are display transformations only; stored paths and lookup URLs stay absolute/full. Distinct paths can share the same parent/current display; that ancestry loss is the approved trade-off. For the same reason, the cwd line is hidden only when the stored absolute Launch and Active paths are identical strings, never because the displays match; Launch keeps its spelling while Active is canonicalized, so an equivalent but differently spelled path (for example through a symlink) still shows cwd. In the common case, where Active is the working directory, the spacer row stays blank; when the agent works elsewhere, cwd fills it, so the footer height does not change.

Layouts respond to width: wrapped repository/PR lines stay on the same content column as the first line; 100+ columns may show the large context numeral; 40–99 columns keep the padded eight-cell numbered plates and use a compact gauge. The track's inline readout has one real blank cell on each side, including Unknown. The number scale retains as many labels (`0 10 … 70 … 90 100`) as fit without ruler ticks. Below 40 columns a minimal fallback keeps every field with wrapped inline labels, starting with the CMP plate; it has no blank spacer row because its ROOT row already separates the header, and a differing cwd line follows ROOT, before 01 ACT. Values wrap rather than truncate. Continuation rows leave the plate column plain, without colored tabs. Corners and side stubs remain; there is no continuous top rule.

The header's Thread Rail has a full-cell root lamp, blank separator, bright `ROOT` panel, up to six unit marks and an exact **AU (Active Units)** badge. ROOT's right edge aligns with the wide context divider and the badge's left background edge with context captions when anchors fit; otherwise activity right-aligns with corner clearance or wraps to its own row. Known counts are zero-padded to two digits and Unknown keeps a bare `?`, so 0–99/Unknown use a seven-cell badge (` 00 AU `, ` 03 AU `, ` 12 AU `, `  ? AU `); 100+ widens it with the exact value. Rail marks yield first at tight widths, then activity moves to its own row. Neither title nor total is clipped to preserve decoration.

ROOT reflects the root session's public `isIdle()` state, independently of AU. AU is the optional pi-subagents native active-work total, including queued/pending items and a workflow container as one; it is not a count of exactly running agents. Unknown data is `? AU`, distinct from confirmed `00 AU`. Native adapter snapshots always supply root state; a renderer used without activity has a static hatched unknown lamp. ROOT stays bright even while Idle.

## Palette and context semantics

The palette is fixed, not taken from the host theme: field `#000000`, primary `#c0fe04`, text `#ffffff`, secondary text `#cfcfcf`, plates `#555555`, surface/band/track `#1c1c1c`, warning `#d79e52`, high/error `#f24723`, and graphic grey `#717171`. CMP uses an approved Marathon-reference count palette (background / text, with truecolor contrast): 0 and Unknown plate `#555555` / `#ffffff` (7.46:1), 1–2 violet `#5200ff` / `#ffffff` (7.49:1), 3–4 pink `#ff15bd` / `#000000` (6.09:1), 5+ high `#f24723` / `#000000` (5.70:1). It is a product-specific choice, not an official brand specification. The only mixed colors are the warning and high gauge zones, 20% of each over black (`#2b2010`, `#300e07`). USG adds three Marathon-sourced provider colors with their used and burn-out mixes, and one neutral ghost grey `#333333` for lost squares; see [USG usage limits](#usg-usage-limits). Pi's `theme.style` converts these colors for truecolor or 256-color terminals; the host theme and settings are not changed.

Context is read from the host on every render. The scale is the auto-compaction budget: Pi compacts once context tokens exceed the window minus the effective `compaction.reserveTokens` (model override, then ordinary setting, then 16384), so the gauge, numeral, 70/90 tones and readout all use `window − reserve` as 100%. Disabled auto-compaction, a reserve that leaves no positive budget, or a setting Pi would reject keeps the full window. Gauge cells cover 0–100%, and a cell lights when any of its slice is used, so only true 0% is empty. Above 70% is warning and above 90% is high; exactly 70 or 90 stays in the lower tone. Unknown, missing, or non-finite usage is a hatched track with `?`, never 0%. The inline readout shows host-reported context tokens over the budget rather than repeating the numeral's percentage, at every width. Tokens take the window's unit and precision so the pair reads as one fraction: whole `k` for k-sized windows (`84k/200k`; 400 tokens is `0k/200k`) and one-decimal `M` for million-sized windows (`0.1M/1.0M`). Unknown tokens read `?`, never `0k`. Values over the budget or below zero are shown as-is in the readout and numeral; only the gauge's graphical extent clamps. A missing or invalid context window omits the `/window` suffix and tokens use their own scale.

## USG usage limits

The pink ` 04 USG ` plate (bold black `#000000` on the Marathon pink `#ff15bd`, the CMP 3–4 pair, 6.09:1) shows remaining subscription quota for three providers in a fixed order: Codex `GPT`, Claude `CLD`, Kimi `KMI`. Only 300-minute (5H) and 10080-minute (WK, week) windows are shown; other lengths and CodexBar's extra (model-scoped) windows are ignored.

**Fixed columns.** Each provider is a column: its tag, then one slot of eight squares per window, one cell apart, for example `CLD ■■■■■■■■ ■■■■■■■■` (seven lit squares and one grey ghost, then eight lit). The renderer declares each provider's window shape, which is a layout declaration rather than a parse rule: Codex `[WK]` (it reports no 5H window today), Claude and Kimi `[5H, WK]`. A column is `3 + 1 + 8·n + (n − 1)` cells for n declared windows (Codex 12, Claude and Kimi 21), and columns are three cells apart, so the full row is 60 cells. The width is the same in every state (pending, failure, data, stale, none), so the meters never move while polling. Within a column, windows are always in 5H, WK order, so a slot's position names its window. A declared window that a sample does not report leaves its slot blank. **Exception:** an undeclared window that a sample does report (for example a Codex 5H window) is still shown, so a real limit is never hidden. It takes its 5H/WK place and widens that column, which moves the later slots and columns. This is the only case where columns shift; it means the declaration should be updated.

Each square is 12.5% of the window. Remaining is 100 − used, clamped to 0–100, and a square stays lit while any of its slice remains: `ceil(remaining / 12.5)` with a 1e-6 tolerance so float noise on a boundary does not light another square, but never fewer than one while any quota remains: only exhausted quota is all dim. Every square is `■` (U+25A0), so the full eight-square bar keeps its shape and the lit squares read as a fill level. Lit squares are in the provider's lit color; lost (used-up) squares at rest are ghosts in one neutral grey, `#333333`, for every provider (1.66:1 on black: quiet, but visible where the old per-provider used tints at 1.1–1.7:1 nearly vanished). Those used tints remain only in the edge pulse's dim frames and the burn-out's last frame. **Accessibility:** lit and lost are distinguished by luminance and hue, not shape. Lit against the ghost is 12.63:1 for GPT `#ffffff`, 4.08:1 for CLD `#ff5c00` and 2.28:1 for KMI `#2555fc`, the weakest pair and below the 3:1 non-text guideline. The tag and the countdown row remain, but the lit count itself is carried only by that contrast.

| Provider | Tag | Lit | Lost (ghost) | Pulse/burn used (20% over black) | Burn-out mid (50%) | Lit contrast on black | Lit vs ghost |
| --- | --- | --- | --- | --- | --- | --- | --- |
| `codex` | GPT | `#ffffff` | `#333333` | `#333333` | `#808080` | 21:1 | 12.63:1 |
| `claude` | CLD | `#ff5c00` | `#333333` | `#331200` | `#802e00` | 6.8:1 | 4.08:1 |
| `kimi` | KMI | `#2555fc` | `#333333` | `#071132` | `#132b7e` | 3.8:1 | 2.28:1 |

The lit colors come from the new Marathon (2025–26). GPT is the exact live Marathon site foreground token `#FFFFFF`, “White, primary foreground”; it also matches OpenAI's monochrome brand. CLD is the exact live Marathon creator-portal token `#FF5C00`, “Signal orange”, which the portal uses for error emphasis; it is recorded in the product owner's industrial-os-references color source records. KMI is an **artwork sample, not an official token**: the per-channel median of the brightest-saturated quarter of pixels (saturation ≥ 0.6, value ≥ 0.5) in the blue runner panel (x 1365–1920, y 0–570, hue 200–250°) of the Marathon reveal key art ([PlayStation Blog, 2025-04-12](https://blog.playstation.com/tachyon/2025/04/94dff7ea964e0baac6a6066aaeee2959e36fac42.jpg)). None of them is a Bungie-declared mapping to these AI providers; that mapping is product-specific. The mixes are per-channel c·0.2 and c·0.5 over black, rounded to nearest with ties up. Tags are bold in the lit color. The bold KMI tag (3.8:1) is below the 4.5:1 text guideline; the product owner accepted it as an accent, like the PNYTL pink light, and the secondary-grey text row and the squares still carry the information. CLD `#ff5c00` is close to the HIGH/error `#f24723`; it is used only for USG squares and tags, never for state text.

A plain continuation row (no plate tab) sits directly below the squares. Each window's countdown to `resetsAt` is left-aligned under its first square in secondary grey `#cfcfcf`; real 5H and WK resets produce at most five cells (`5d15h`), so they fit inside the eight-cell slot. The day count is not capped: a distant or malformed reset date can produce a longer countdown, which widens that slot rather than overlapping; like an undeclared window, this is an exceptional column shift. The adapter supplies the wall-clock `now`; the renderer reads no clock. Minutes round up, so a positive span never reads `0m`:

| Remaining time | Format | Example |
| --- | --- | --- |
| < 1 h | `Nm` | `41m` |
| < 10 h | `HhMMm` | `4h03m` |
| < 24 h | `HHh` | `12h` |
| < 10 d | `DdHh` | `5d15h`, `6d2h` |
| ≥ 10 d | `DDd` | `12d` |

`reset` means `resetsAt` has passed and the data is behind; `?` means a missing or invalid `resetsAt`. When every column on a line has no text (all `none`, none stale), the text row is omitted.

Unknown is never success-shaped. A provider that has not answered yet shows eight grey `#717171` `········` pending cells in every declared slot, with `pending` below its first slot in secondary grey, the same quiet treatment as `GitHub pending`; pending dots are deliberately a different shape from the `????????` failure cells. A failure without earlier data (CodexBar error payload, malformed output, timeout) shows grey `????????` in every declared slot and amber `timeout` or `failed` below the first, like the other unavailable states; the raw CodexBar message is never shown because it is untrusted and can name the account. A successful sample without 5H/WK windows shows grey `none` in the first slot, padded to the column width, with no text below. One unknown window shows `????????` with `?` below while the other window stays normal. State words sit under the first slot and fit inside an eight-cell slot; a word may never extend more than two cells past its column's right edge, so at least one blank always remains before the next column's text.

After a failure with earlier data, the last good windows stay visible and are marked **stale**: the tag dims to grey `#717171` and the sample's age appears in amber under it. Data older than 15 minutes (CodexBar's `updatedAt`, else the time it was received) is stale in the same way. The provider mixes are not used for the dimmed tag: CLD's and KMI's 50% mixes are 1.7–2.3:1, too faint for text, so every stale tag uses the one grey (GPT's `#808080` would be readable, but would make its stale tag look unlike the others). The age fits under the three-cell tag:

| Age | Format | Example |
| --- | --- | --- |
| up to 59 min | minutes, rounded up (a positive age never reads `0m`) | `16m` |
| to 24 h | whole hours, at least `1h` | `5h` |
| to 100 d | whole days | `2d` |
| 100 d or more | capped | `99+` |

Whole provider columns wrap together with their text rows, using the fixed widths, so wrap points do not depend on state either; continuation rows leave the plate column plain. At 100 columns all three fit on one line; at 48, Codex and Claude share the first line and Kimi wraps. Below 40 columns the minimal layout shows an inline ` 04 USG ` label, the first column beside it when it fits, and further columns from the first column. A column wider than the line splits between its tag and window slots, and a slot wider still wraps onto its own rows, so no square, countdown or state word is clipped. Fetching is slow (about 20 seconds each for Codex and Claude), so the row can show pending for a while after startup; it refreshes five minutes after each round completes.

## Tatsu status

The optional pi-tatsu-status-bar **public v1** snapshot produces one EXT entry of two-coloured plates, one per component: `[ TCLI ][ ▲ UP×1 ]  [ AWKS ][ • OK ]`. Each plate is a label half, then a state half, with no gap between them. The label half is ` TCLI ` or ` AWKS ` (tatsu-cli or agent-workspace, one pad cell each side) in bold secondary grey `#cfcfcf` on surface `#1c1c1c`. The state half is ` <shape> <CODE> ` (one pad cell each side, one space between shape and code) in bold field black `#000000` on the state's colour. Two field-black cells separate the plates. The entry starts at the EXT content column like any other status, with no prefix; as the first entry it follows ` 05 EXT `, otherwise it occupies its own continuation line.

| State | State half | Background |
| --- | --- | --- |
| current | ` • OK ` (the small `•`, not `●`) | Acid `#c0fe04` |
| behind | ` ▲ UP×N ` when the count is known (no space before `×`), otherwise ` ▲ UP ` | Amber `#d79e52` |
| repair | ` ▲ FIX ` | Amber |
| local_changes | ` ◆ EDIT ` | Amber |
| behind/repair with localChanges true | The above, then `◆ EDIT ` in the same half, e.g. ` ▲ UP×1 ◆ EDIT ` | Amber |
| missing | ` ✕ MISS ` | Red `#f24723` |
| not_runnable | ` ✕ NRUN ` | Red |
| unavailable | ` ✕ UNAV ` | Red |
| checking | ` · CHK ` | Graphic grey `#717171` (background fade with motion) |
| inactive component in an active snapshot | ` · OFF ` | Graphic grey |

Plates break only between components: when both plates do not fit a line, the second moves to the next line at the same content column, and in the minimal layout the first plate sits beside the ` 05 EXT ` label whenever it fits there. Only a plate wider than its whole line splits, at its inner spaces like any other status; the pad cell at that break is dropped, so the half's coloured run ends at its last glyph (for example ` TCLI  ▲` then `UP×1 ` at 12 columns). Every line remains width-bounded.

Only valid checking/completed snapshots replace the provider's raw `tatsu-status` entry. The provider re-checks every five minutes and briefly reports both components as checking each time; once a completed result has been shown, a refresh keeps that last completed result on screen, so the text only changes when a new result differs. `CHK` appears only before the first completed result (session start, or after inactive, invalid or absent data cleared it). They remain visible when the provider's own text is hidden. Absent/invalid/incompatible/inactive snapshots retain raw text exactly through the existing sanitizer/style/wrap path, or no entry if the provider clears it. Unknown is never success-shaped. The footer does not register a formatter, change provider configuration, run checks or poll.

Four decorations use only the existing single timeout; the state half carries every one and the label half never changes:

1. **Appearance:** none/raw → valid active, including reappearance, draws in from the entry's first cell with the same USG helper and `USAGE_SWEEP_CELLS_PER_TICK` (three cells per 50 ms tick). Cells ahead are blank field, the three-cell front is LOCKED (bold black on acid), cells behind are the settled plates. The draw-in lasts until the front reaches the entry's last cell: 9 ticks (450 ms) for the 26-cell ` OK `/` OK ` entry and 10 ticks for ` UP×1 `/` OK `; longer counts/local edits get enough ticks for their initial width. Wrapped lines sweep together from their own first content cell, leaving the EXT label alone. All content settles at the end, even if newer data grew. During footer boot the existing EXT boot treatment applies instead: the entry's text is restyled like other EXT text, without plate backgrounds, until it settles.
2. **Checking scan and fade:** the shape cycles `· → • → • → • → ·`, one step per 150 ms (750 ms per cycle, never the large `●`), in black. The ` · CHK ` state half's background gently fades in a 1200 ms/eight-step triangle wave: `#717171 → #7b7b7b → #868686 → #919191 → #9c9c9c → #919191 → #868686 → #7b7b7b`. Text stays black. Both components share the motion epoch and one cadence, so their backgrounds fade in phase. This is a gentle low-contrast fade, not a flash: adjacent steps differ only slightly, it only lightens from graphic grey, and there is no polarity change. Motion off uses a steady `#717171`. Draw-in/footer boot hold the scan and fade until their own treatment settles.
3. **State-change latch:** a state/count/local-edits flag change between completed results latches that component's state half once: tick 0 LOCKED (bold black on acid), ticks 1–2 inverted (bold state colour on field black), then settled (150 ms total). First discovery, unchanged checking→completed and inactive transitions settle. Checking preserves the previous completed baseline; invalid/inactive data clear it. New changes interrupt with latest content. Boot/draw-in suppress latches, without replay.
4. **Attention beacon:** behind/repair's `▲` cell pulses in the last 150 ms of each 4000 ms motion-epoch period, never opening on a pulse: 50 ms black `▴`, 50 ms `▴` in `warnDim` `#6c4f29` (50% amber on black), 50 ms `▲` in `warnDim`, then the settled black `▲`, always on the amber background. Only that cell's size/ink change; code, count and local edits stay unchanged. Draw-in, footer boot and latch hold it off.

Motion off draws everything immediately with a steady grey ` · CHK `, no latch/beacon/draw-in. Resume replays nothing and starts a fresh epoch. The pre-styled entry is excluded from ghosts and re-strikes. Shapes and codes together carry every state, never colour alone.

Contrast (WCAG relative luminance): label half `#cfcfcf` on `#1c1c1c` is 10.94:1. Black on the state backgrounds is 17.42:1 on acid (OK and the LOCKED latch/draw-in front), 8.90:1 on amber, 5.70:1 on red and 4.30:1 on graphic grey (CHK and OFF, and the fade's lowest step), rising through 4.96, 5.77 and 6.66 to 7.65:1 at the fade's `#9c9c9c` peak. The inverted latch ticks use the same pairs reversed. Grey is below the 4.5:1 text guideline; it is accepted for the placeholder and inactive states, whose shape and code also carry the meaning. The beacon's `warnDim` on amber is 3.19:1 for 100 ms of a glyph that is otherwise black.

## PNYTL mode plate

One constant white 16-cell body (` ⌑ PNYTL // LTE `), with one exterior black-field gap on each side, occupies 18 cells. The exact `⌑` icon, title and slashes are black and bold; the icon cell alone also carries the activity light described under motion. Mode letters are bold: LTE `#004fe8`, FUL `#5200ff`, ULT `#c00092`, REV `#006e70`; OFF/CHK/UNK `#555555`. Black pulses use `#000000`. Truecolor contrast against white is at least 5.74:1. These assignments are product-specific; FUL uses the Marathon violet, cobalt/pink are contrast-adjusted mixes and teal is new. No pastel or background animation is used. Pi handles existing 256-color conversion; real-terminal color fidelity is not certified.

The plate moves to a model-band continuation, at the same column, when model text naturally needs the space; no model/status field is truncated to fit it. Because the numeral panel widens at 100%+, the plate shifts with the digits, as ROOT does with the divider. Below 40 columns it follows the model in the minimal wrapped layout, before USG and EXT. Renderer snapshots without the optional field retain their previous layout; the native adapter always supplies a state. CHK is the bounded initialization turn, UNK is unavailable, and OFF requires an observed explicit status clear. Ponytail 4.13.0 status emission must be enabled and pi-status-bar must load before it to capture initial OFF; otherwise an absent key remains UNK until a later explicit emission. Known current labels come from the public status map. Color is never the sole mode signal.

## Motion

Motion is decoration only. A supplied-time/seed plan provides varied boot treatments across actual paths, branch and Git status text, title, chips, model, statuses and context readout; the Git status text waits on a grey band, then settles to its ink. Corners draw in and the standalone center `┼` makes a small calibration nudge once every six seconds. Boot never masks ROOT/AU. The CMP plate shows its current count from the first frame; for the first two boot ticks it swaps its approved background and text colors, keeping their contrast, then settles. CMP is not a re-strike or ghost target. Current large context digits reconstruct square by square from grey/current color; old-only pixels clear immediately and target geometry updates immediately (**new shape only**, not the browser's old-to-new retained-pixel morph). The exact small readout and graphical fill are immediate, even through rapid retargeting or Unknown transitions.

Fresh re-strike plans start every 4–6 seconds start-to-start. Whole-plan shuffling lets ROOT or AU lead or follow other plates/numeral/caption patches; each panel is selected independently about half the time. Re-strikes affect backgrounds, lettering colors and padding without changing characters/current digit occupancy. Ghosts have a separate A+B duration plus 2.2–4.2 second wait; fill glitches affect only the currently filled track. Readout including padding, unfilled/Unknown gauge, all activity cells during ghosts, other extensions' styled content, lamp/separators/unit marks/gaps during re-strikes remain protected. Plans resolve against current geometry and eventually recover fully.

Working lamp cadence is 500 ms acid / 300 ms dim; Idle is static dim. Ambient plans run in both Working and Idle, without focus gating. The adapter owns one bounded, unref'd decoration timeout, with 50 ms transient granularity and renderer-selected sleeps, never a free-running interval or data collector. `/footer-motion off` settles all motion immediately but preserves live ROOT/AU, CMP, context/model/statuses, USG values and countdowns, and Git/PR updates. Resuming starts fresh without catch-up. No v9 render-cost or full-host repaint-performance measurement is claimed.

Tatsu’s four decoration exceptions are the appearance draw-in blanks, checking-placeholder size-only glyph scan with gentle state-half background fade, state-change style latch, and attention-triangle size-only beacon, described above. They change no state codes/counts and use no additional timer.

USG decoration is style-only with two exceptions: the row boot's draw-in, which leaves cells it has not reached blank; and the edge pulse's size change on a lit square. The burn-out below changes no glyph: every square is `■`, and a lost square keeps its burn colors for 600 ms before it settles to the grey ghost. During a burn-out the lost squares' white and lit frames therefore overstate the remaining quota; this known exception is kept pending the product owner's live review. An undrawn cell is blank, as with the header corners drawing in, never a stale or wrong value: every cell that is drawn shows its current character, and countdowns, glyph positions, text and every other value are always current from the first frame they are drawn. **Row boot:** when the row appears (CodexBar is first detected, often well after the footer's own boot, or reappears after being hidden), and when the row is already present as the footer boots, a draw-in builds it left to right, like a terminal writing it, in the existing boot vocabulary. Its front starts at the left edge of the ` 04 USG ` plate and advances three cells per 50 ms tick; on tick k it has reached (k + 1)·3 cells. Cells it has not reached are blank field. The three cells at the front take the path lock's one-tick latch (black bold on acid) with their current character; blank cells inside the row latch too, so the front reads as one moving band. Cells behind it are settled: provider colors, pending dots, `?`, countdowns and stale ages. The plate's eight cells take part like any others, from blank through the latch to the settled pink plate. The text row trails one tick behind (k·3 cells on tick k), so the line below builds just behind the line above. Each wrapped line sweeps from its own left edge at the same time as the first: framed continuation lines measure from the plate column, whose blank cells stay blank, and in the minimal layout each line measures from its first column. The boot lasts 27 ticks (1350 ms): enough for the widest natural row of 78 cells (plate, gap, and all three columns with every window, including a 5H window Codex does not declare), plus the text row's lag. The 69-cell row of today's declared shapes is settled by tick 23 (1150 ms). When the boot ends everything is settled and drawn at any width, so an unusually long row can never stay hidden. Data that arrives during the boot is simply drawn current when the front reaches it, with no fill-in. **Fill-in:** when a provider goes from no data (pending, or a failure without data) to data after any row boot, each cell latches left to right one per 50 ms tick, with all of the provider's windows in parallel (400 ms for eight squares). Before its tick a cell shows its current glyph (`■`, `?`, `·` or a letter of `none`) in graphic grey `#717171`, on its tick it is white `#ffffff`, then it takes its settled ink. A countdown settles from graphic grey to secondary grey when its window's last square latches. A newer sample during a fill-in does not restart it; only another loss and return of data does. **Edge pulse:** the edge square is the highest lit square of a window with 0 < remaining < 100. With its slice fraction f = (remaining − 12.5·(lit − 1)) / 12.5, in (0, 1], its period is P = 600 + 3400·f ms, and the last 150 ms of each period is a pulse in three 50 ms steps: `▪` (U+25AA, a smaller filled square) in the lit color, `▪` in the used color, `■` in the used color, then the settled lit `■`. A period never opens on a pulse. A draining slice pulses faster, but never more than 1.7 times a second (at most two pulse onsets in any second), under the three-flash guideline; it runs Working and Idle. `▪` is only ever the lit edge square during its pulse, never a lost, pending, unknown, fill-in or burn-out cell, so the lit count is unchanged in every frame. GPT's used color is the same `#333333` as the ghost, so for GPT the 50 ms dim `■` step looks like a lost square. This is the one USG decoration that changes a glyph: a size-only change on a lit square, following the precedent of fill glitches swapping track glyphs. **Burn-out:** when a newer successful sample for the same provider and window lights fewer squares, every lost square plays once, simultaneously: 0–100 ms white `■`, 100–250 ms lit `■`, 250–400 ms the 50% mix `■`, 400–600 ms the 20% mix `■`, then the settled grey ghost `■`. GPT's lit color is the same white as the fill-in's latch tick and the burn-out's first frame (0–100 ms), so for GPT those frames read as lit. First discovery, increases (resets), failures that keep the old sample and unknown transitions settle without a burn; newer data interrupts and settles to the latest. A running row boot holds every edge pulse and burn-out on the row off, as a running fill-in does for its windows, and a burn-out holds its window's pulse off. All of these wake from the existing decoration scheduler: row-boot front and fill-in steps on the 50 ms tick, pulse and burn steps on exact millisecond boundaries, never a new timer, free-running interval or fetch. `/footer-motion off` renders the row settled: no row boot or fill-in, the edge held as a steady lit `■`, burn-outs cancelled; resuming starts fresh and never replays a boot, fill-in or burn that would have happened while motion was off. Apart from its own row boot, fill-in, pulse and burn, USG is excluded from the footer boot, re-strike and ghost treatments: its plate has no re-strike zone and its content is pre-styled text. Countdowns are live values, not decoration: while the row shows a countdown or stale age, the adapter repaints when one of them can next change, with or without motion.

PNYTL is excluded from all boot, re-strike, ghost and background treatments. Its one continuous signal is the activity light: while Ponytail's own status reports `●` (the agent is running a turn) with a confirmed LTE/FUL/ULT/REV mode, the icon cell alternates between black `⌑` and a pink `•` (U+2022, chosen smaller than the icon; `#ff15bd`, the CMP 3–4 pink) on the white body, 50 ms each, toggling on every decoration tick. That is 10 blinks a second, the fastest the 50 ms tick allows, chosen by the product owner to read as rapid activity, eight times ROOT's 500/300 ms cycle. While active, the footer repaints every 50 ms. Pink on white is about 3.4:1, an accent below the 4.5:1 text guideline chosen by the product owner; it is distinct from ULT's magenta letters, and ROOT and the text remain the readable activity signals. Motion off holds the light lit while active. `○`, OFF, CHK and UNK show the static icon. The light never changes the plate's width, text or other cells, and it is independent of the mode-letter burst. First confirmed discovery settles. On a subsequent real confirmed mode change (except OFF), two different nonempty subsets of the three letters are drawn once from the existing seeded RNG. Black pulses occupy 100–200 ms and 350–450 ms after the transition; all other frames use the new mode's saturated ink. Text is current from frame zero. Interruption cancels the burst and settles the latest mode; same-mode status updates and checking/unknown transitions do not replay it. OFF/CHK/UNK settle immediately. Motion off cancels it; resuming samples current state without replaying off-time changes.

A conservative start guard reserves 1800 ms per burst, extended to at least 1100 ms after each observed burst frame/recovery. The adapter retains the budget through motion toggles and tree/footer replacements. Late callbacks skip missed pulse phases and reserve quiet time from actual recovery, rather than catching up. Tests count at most two deliberate opposing pulse pairs per letter in rolling one-second windows. The activity light deliberately exceeds three flashes a second (ten, tested as at most ten in any second): it is a single character cell, far below WCAG's general flash-area threshold, but it is the footer's fastest motion and `/footer-motion off` holds it steady. This is scoped to PNYTL, **not whole-footer WCAG certification**: existing ambient motion has not been formally audited. Reference: [WCAG 2.2 three flashes or below threshold](https://www.w3.org/WAI/WCAG22/Understanding/three-flashes-or-below-threshold.html).

## Accessibility and platform behavior

The footer is text-first and keyboard interaction remains Pi's responsibility; this extension adds no focusable controls. Every state has text: the Git status says clean/modified/status unavailable, the context tag says WARN/HIGH/UNKNOWN, and failures say unavailable with a reason, so color is never the sole signal. Each Tatsu state half pairs its background with a shape and a code; its contrast ratios are recorded under [Tatsu status](#tatsu-status). Every emitted line is bounded to terminal width, including widths narrower than a single wide glyph. There is no host reduced-motion signal, so the session command is the pause/reduced-motion control.

Paths, branches, URLs, errors, and status content are treated as untrusted terminal text. Control characters, bidi controls, OSC links, and non-style escapes are removed. Other extensions' SGR color sequences are preserved, not recolored. Their resets restore the footer field instead of the terminal default, and each status row is reset before footer padding and frame glyphs. Supported colon-form RGB/indexed foreground and background colors are normalized to Pi's semicolon form so their styling also survives wrapping.
